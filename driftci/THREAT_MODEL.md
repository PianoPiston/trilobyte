# DriftCI security model

DriftCI handles two untrusted inputs: public web content and source repositories. The prototype uses constrained parsing and bounded reads rather than agentic execution.

## Hard boundaries

- **No repository code execution.** The scanner reads allowlisted text manifests and source extensions. It never runs package lifecycle scripts, project tests, generated tools or repository-provided executables.
- **Selective, bounded repository reads.** Connections accept only canonical public `github.com/owner/repo` HTTPS URLs. The backend validates an immutable commit, reads tree/dependency-graph metadata and fetches relevant manifests, native declarations and selected source at that commit. Archives, clones, package installation and repository execution are prohibited. File-count, total-byte, per-file, concurrency and time bounds apply regardless of repository size. Security inventory includes scoped test, example, documentation and bundled dependencies; application-model matching excludes those scopes. Redirects are disabled and GitHub credentials never go to raw hosts or through Context.dev.
- **Coverage is explicit.** Tree truncation, missing/failed/oversized reads, parser failures and budget skips leave source or manifest coverage partial. Advisory-query coverage is separate from source coverage: unresolved declarations, unsupported native comparisons, batch pagination, failed full-detail retrieval and package/time limits remain visible. Missing evidence is not treated as absence or safety.
- **Bound metadata transport.** Public `api.github.com` JSON may travel through Context.dev as bytes. Host/scheme/credential rules, response size, base64, content type, JSON shape and GitHub error envelopes are validated. Selective raw source never uses this transport. Direct GitHub fallback errors and transport identity are retained. Only supported exact package/version tuples go to OSV; unresolved declarations and native components do not become registry queries.
- **Relevant official watches.** Model/package watches are selected from fixed built-in mappings. Custom watches require a public HTTPS URL, reject embedded credentials and local/private IP addresses, and are capped at 12. The URL goes to Context.dev; repository source contents do not.
- **Research host validation.** Scoped queries contain an official `site:` restriction and returned result hosts are checked again server-side. Off-host results are discarded.
- **Web text is data.** Context.dev responses are length-capped, sanitized and parsed as text. They are never evaluated or interpolated into shell commands. Research titles, highlights and diffs are separately excerpted.
- **Bounded observation storage.** Normalized snapshots are capped at 120 KB, each source retains at most 12 observations, and public API responses omit internal snapshot text. Observations are created only when a later normalized hash differs from the previous baseline.
- **Rate and credit controls.** Context.dev requests share a 6-hour cache, 6.2-second minimum interval, six-scrape/one-search refresh caps and a daily 10,000-credit default ceiling. Settled ordinary usage, monitor spent/reserved credits and in-flight ordinary reservations reduce availability; in-flight reservations are released in `finally` paths. Monitor creation checks this shared availability before its POST. Fresh cache remains available when no new request is permitted. Retained prior commitments can exceed the configured ceiling; the UI exposes that condition rather than resetting it. The local ledger is not authoritative account billing.
- **Reachability is not exploit proof.** Configured-model context is required for bare `o1`–`o5` identifiers; FFI variables are not model evidence. Exact identifiers establish source presence, including possible SDK catalog definitions. Advisory ranges require full OSV advisory records, not batch descriptors. Matches persist dependency scope and evidence manifest. Application, bundled, test, example, documentation, dependency-graph and native evidence are distinct. Only application manifests can receive direct deterministic patches. Exploitability still requires deployment-aware validation.
- **Human decisions persist.** Web signals support reviewed/monitoring/resolved states. Vulnerability resolution goes through an ordered incident checklist. Web content cannot resolve an incident by itself.
- **Secret hygiene.** API keys come from environment variables, never appear in API responses or evidence receipts, and are excluded from logs. Repository source is not sent to Context.dev. OSV receives only package ecosystem/name/version queries.
- **Monitoring claims are precise.** `watcher.enabled` refers to a local periodic task. Context.dev owns a separate real hourly monitor and remote run/change records, identified in Web Watch. Baselines, failures, skips and no-change completions are not alerts. Monitor text and citations are untrusted, host-filtered evidence and cannot create automatic patches. Context.dev monitor webhooks are not implemented; the optional HMAC GitHub webhook is separate.

## Release Room and live-event boundary

- **Read-only release integration.** Release ingestion uses public GitHub REST metadata and bounded diffs at validated head commit identifiers. PR head/SHA fields, review states, check identifiers, timestamps, paths and excerpts are type-checked and size-capped. GitHub token authorization is sent only to `api.github.com`; raw source retrieval receives no token. Webhook verification uses a separate secret.
- **Verified webhook input.** `POST /api/github/webhook` requires a configured secret and a valid `X-Hub-Signature-256` over a maximum 512 KB raw body. The connected repository and GitHub event type are checked before accepting the delivery. Delivery IDs are deduplicated. Subsequent reconciliation reads current GitHub state; webhook text alone does not establish a CI result or release approval.
- **Current code only for matching.** Model matching includes current non-deleted paths and added/context diff lines. Removed lines and deleted files do not represent the PR head. The base-branch source index and PR head diff are separate evidence classes.
- **Explicit coverage limits.** The targeted source index is bounded at 1,600 records / 32 MB, with a 2 MB per-file cap. Initial repository connect is PR-index-only; old-head detail cannot stand in for a new head. PR detail takes up to 30 file patches per PR with 12,000 characters per patch, and up to 50 reviews/check runs. Omitted binary/large-file patches remain incomplete. Stable limitations are not silently converted into complete evidence or redownloaded each poll.
- **No synthetic activity.** Initial retained documents and PR imports are baselines. Only a later normalized source hash, a changed GitHub fact or an actual local decision creates their respective event types. Historical replay is distinctly labelled. A failed or deferred fetch preserves retained records without claiming freshness.
- **Tamper-sensitive release references.** A local decision stores the PR head and evidence fingerprint, including source-state facts and check-run IDs/status/conclusion. Later material changes expire the decision reference. Human acknowledge/resolve state by itself does not pretend to alter external facts.
- **Ready is constrained locally.** Ready requires fresh GitHub retrieval health and complete bounded file/review/check coverage; pending/failing checks block it. A hold can preserve a known limitation. DriftCI records observed CI results, never runs the application’s checks by invoking its code, and no reported checks does not mean passing CI.
- **Local owner strings, not verified identities.** The public demo’s reviewer and note are free-form strings with length bounds. They are useful for showing the workflow, not an authenticated corporate approval. Release decisions do not approve or merge GitHub PRs, deploy code or alter CI.
- **Durable bounded browser stream.** Event data uses the same normalized public records as the rest of the API. Polling reads a bounded recent PR window, and SSE serializes records without exposing credential fields. React renders all upstream text as data; Markdown reports download as text with content-disposition handling.
- **Quota-aware persistence.** ETags and retry metadata persist across restarts. GitHub reset headers and `Retry-After` are honored; a bounded `/rate_limit` lookup can resolve a header-less 403. Suppressed retries make no upstream PR request. Request errors are bounded display messages without authorization headers.
- **Least-privilege token requirement.** Release Room performs no GitHub writes. A supplied token should therefore have only contents, pull-request, checks and required metadata read access. Legacy remediation APIs remain outside the Release Room; introducing a writable token would require a separate review of those compatibility routes and their authorization.

## Public-demo trust limits

The deployed evaluation workspace is public by design. Visitors can select a public repository, affect cached scan state and enter named local decisions. This is acceptable only for a known read-only demonstration and not for authoritative organizational review. Anonymous GitHub capacity can be exhausted even with ETags and retry suppression; cached evidence remains visible and its freshness warning is retained.

Local Context.dev pacing and the 10,000-credit daily reserve protect this single process/workspace. They are not a multi-tenant or account-wide quota coordinator. Public repository changes can shift the derived watchlist, so budget exhaustion remains visible and ordinary six-hour cache reuse is preserved. No repository source contents are sent to Context.dev; custom URL egress protections are described above and do not eliminate all DNS/egress risks.

Do not use private repositories, secrets, personal information or sensitive reviewer notes without adding authenticated workspace access, encrypted storage and appropriate egress controls. The public deployment does not provide tenant isolation or tamper-proof audit ownership.

## Production follow-ups

Add organization SSO and role-based incident ownership, encrypted secrets and database storage, DNS-aware egress policy for custom watchers, per-tenant budget isolation, GitHub App/private-repository support, incremental per-commit indexing, exhaustive CI-based SBOMs, isolated application-owned validation, immutable evidence-object storage, tenant isolation and audit-log export.
